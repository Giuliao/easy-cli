# SMB 小工单项目本地开发约束

## 项目上下文配置

不要假设或硬编码本机 SMB 仓库路径。需要定位某个仓库时，先按实际任务范围读取相应配置：

    easy config get smb.backend-repo
    easy config get smb.frontend-repo
    easy config get smb.idl-repo

后端重点业务范围为 `mfg_lark_order`。如果所需配置不存在，要求用户提供路径或在 easy 配置中设置；不得回退到历史路径。

实际改动范围以用户本次请求为准。不得因为存在三个仓库就默认修改全部仓库。实现阶段默认使用隔离 worktree，避免影响当前目录；若用户明确要求在当前分支开发，则遵循用户要求。基线分支必须来自用户输入、任务文档或远端分支事实，不得硬编码历史基线。

后端设计遵守 Handler、Service、Repo 三层职责和仓库 AGENTS.md；复杂且可复用的业务能力才考虑 Domain，不做无意义抽象。涉及 service 文件的修改必须同步设计单测，满足增量与文件覆盖率门禁。

## 开发阶段

### 资源控制原则

开发阶段应优先保证当前系统和其他任务可用，默认采用小并发、可中断、有限范围的方式执行测试、编译和数据查询。任何可能长时间运行或占用大量 CPU、内存、磁盘和连接数的操作，都应先缩小范围并设置资源上限。

**Go 测试与编译。** 优先使用单个测试或单个包验证问题，例如 `go test ./service/... -run TestName`；需要扩大范围时，使用 `GOMAXPROCS=2 go test -p 2 ./...` 限制 Go 调度器和包级并发。避免在多个终端同时执行全量测试、竞态检测或重复编译；全量操作前先确认机器负载和可用内存。

**并发与后台任务。** 不启动无上限的 goroutine、worker 或重试循环。后台任务应绑定 context，设置并发数、超时、批量大小和退出条件；优先使用项目已有的 SafeGo、errgroup 或封装组件，避免任务失控后持续占用资源。

**数据库与外部查询。** 查询必须带租户等索引条件，并限制结果集；一次性全量查询最多使用 `LIMIT 1000`，只查询必要字段，禁止无条件扫描大表。涉及线上或共享环境时，优先只读、分批、低频查询，避免并发打开大量连接。

**日志与诊断。** 日志不要输出完整 request、快照、密文、Token 或大对象；优先记录 trace/log ID、业务主键、阶段、耗时、数量和脱敏错误码。诊断大问题时先按单个 log ID、时间窗口和 PSM 缩小范围，再扩大查询。

**执行后检查。** 长任务前后检查 CPU、内存、磁盘和进程数；发现系统明显变慢、内存持续增长或 OOM 风险时，立即停止扩大任务范围，终止异常进程并保留最小复现命令，避免通过重复重试进一步放大问题。
